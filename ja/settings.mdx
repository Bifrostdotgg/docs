設定ページは、個々のプラグインではなく、ダッシュボード自体の設定をまとめて行う場所です。サイドバーの <DashboardLink to="settings">**Settings**</DashboardLink>（設定）をクリックして開きます。ページはタブに分かれていて、それぞれがサーバーでのダッシュボードとBotの動作の異なる側面を扱います。

## General（全般）

<DashboardLink to="settings/general">**General**</DashboardLink> タブでは、ダッシュボード全体の動作を設定します。

### 権限のない機能を隠す

有効にすると、現在のユーザーがアクセス権限を持たないダッシュボードのセクションは、グレー表示ではなく、サイドバーから完全に非表示になります。特定の領域にだけアクセスできればよいスタッフにとって、サイドバーがすっきりします。

管理者には、この設定に関係なく常にサイドバー全体が表示されます。

### セットアップウィザード

セットアップウィザードは、Heimdallの主要機能の初期設定を順に案内します。たとえば新しいプラグインをまとめて有効にするときなど、もう一度確認したい場合は、**Re-run Setup Wizard**（セットアップウィザードを再実行）をクリックすると最初からやり直せます。既存の設定がリセットされることはなく、各ステップをもう一度案内するだけです。

## Commands（コマンド）

<DashboardLink to="settings/commands">**Commands**</DashboardLink> タブでは、Heimdallのスラッシュコマンドがサーバーでどのように表示され、動作するかを設定できます。

各コマンドは、個別に次の設定ができます。

- **有効化または無効化**：無効にしたコマンドは、サーバーのDiscordのコマンド一覧から削除されます
{/* docs-manifest-ignore -- /feedback is an example rename target, not a shipped command */}
- **名前の変更**：サーバーの慣習に合わせて、コマンドに独自の名前を付けられます（例：`/suggest` を `/feedback` に変更）
- **説明の上書き**：Discordの入力補完に表示される説明を変更できます

Discordが更新されたコマンド一覧をサーバーに反映するため、変更は1分以内に適用されます。

## Role Permissions（ロールの権限）

<DashboardLink to="settings/roles">**Role Permissions**</DashboardLink> タブは、どのDiscordロールがHeimdallのどの機能にアクセスできるかを設定する主な場所です。仕組みの詳しい説明は [権限](/ja/permissions) を参照してください。

ドロップダウンからロールを選ぶと、そのロールの権限の上書き設定を確認・編集できます。各権限キーには、3段階の切り替えスイッチで現在の状態（**Allow**（許可）、**Deny**（拒否）、**Default**（デフォルト））が表示されます。

## User Permissions（ユーザーの権限）

<DashboardLink to="settings/users">**User Permissions**</DashboardLink> タブでは、ロールベースの権限の上に、ユーザーごとの上書き設定を適用できます。ユーザー単位の上書きは、メンバーが持つどのロールよりも優先されます。そのため、ロールを変えずに特定の人にアクセスを許可したり、ロールでは本来許可される機能から特定の1人だけをブロックしたりするのに便利です。

Discordのユーザー名またはIDで検索してユーザーを選び、ロールの権限と同じ方法で上書きを設定します。

## Server Template（サーバーテンプレート）

<DashboardLink to="settings/template">**Server Template**</DashboardLink> タブでは、サーバーのHeimdallの設定をまるごとJSONファイルとしてエクスポートし、別のサーバーにインポートできます。

### エクスポート

**Export Configuration**（設定をエクスポート）をクリックすると、すべてのプラグインの設定、権限の上書き、automodのルール、カテゴリなど、Heimdallがサーバーについて保存している設定を含むJSONファイルをダウンロードできます。

### インポート

**Import Configuration**（設定をインポート）をクリックし、以前にエクスポートしたJSONファイルをアップロードします。すべてのセクションをインポートするか、特定のプラグインだけを選んでインポートするかを選べます。選んだプラグインの既存の設定は上書きされます。

<Warning>
  テンプレートをインポートすると、選んだセクションの既存の設定は上書きされます。バックアップが必要な場合は、インポートする前に現在の設定をエクスポートしておいてください。
</Warning>

## File Storage（ファイルストレージ）

<DashboardLink to="settings/file-storage">**File Storage**</DashboardLink> タブでは、添付ファイル用の外部ストレージプロバイダーにHeimdallを接続します。デフォルトでは、チケットやModmailの会話に添付されたファイルはDiscord自体のCDNに保存されます。外部ストレージを使うと、Discordがファイルを削除した後（通常は1年後）もファイルを保持でき、ファイルサイズの制限もなくなります。

### ストレージプロバイダー

| プロバイダー | 補足 |
| --- | --- |
| **S3-compatible**（S3互換） | AWS S3、Cloudflare R2、MinIO、その他のS3互換エンドポイント |
| **UploadThing** | インフラの管理が不要なマネージド型のファイルホスティング |
| **Zipline** | セルフホスト型のファイル共有サーバー |
| **FiveManage** | FiveMコミュニティ向けのファイルホスティング |
| **Google Drive** | Google Driveのフォルダにファイルを保存 |
| **OneDrive** | OneDriveのフォルダにファイルを保存 |
| **Discord Channel**（Discordチャンネル） | 予備として、非公開のDiscordチャンネルにファイルをアップロード |

### ストレージモード

- **Oversized only**（サイズ超過のみ）：Discordのアップロード上限を超えるファイルだけを外部ストレージに送り、それより小さいファイルは引き続きDiscordのCDNを使います。
- **All files**（すべてのファイル）：サイズに関係なく、すべての添付ファイルを外部ストレージ経由で扱います。

### オーバーフロープロバイダー

予備のオーバーフロープロバイダーを設定できます。設定したバイト数のしきい値を超えるファイルは、メインのプロバイダーではなくオーバーフロープロバイダーに自動的に送られます。メインのプロバイダーにストレージの容量制限があり、大きなファイルは別の場所に置きたい場合に便利です。たとえば、Discordでは8MBまでのファイルしかアップロードできません。よくある使い方は、Discordチャンネルをメインのプロバイダーにして、S3など別のものを予備として設定する方法です。

### セットアップ

プロバイダーを選び、必要な認証情報（APIキー、バケット名、リージョン、エンドポイントなど、該当するもの）を入力して、**Save**（保存）をクリックします。プロバイダーの選択欄の横にある **Setup Guide**（セットアップガイド）のリンクから、プロバイダーごとの手順付きセットアップドキュメントを確認できます。

<Note>
  認証情報は保存時に暗号化され、保存後にダッシュボードで表示されることはありません。認証情報を更新するには、新しい値を貼り付けて保存してください。
</Note>

## Background Jobs（バックグラウンドジョブ）

<DashboardLink to="settings/background-jobs">**Background Jobs**</DashboardLink> タブには、多数のメンバーのロールを一度に変更する最近のジョブが一覧表示されます。たとえば、XPのインポートやレベル曲線の変更後にレベル報酬のロールを付与するジョブや、全員を新しいMinecraftの連携ロールに移すジョブなどです。各ジョブには、進行状況、変更したメンバーの数、変更できなかったメンバーの数が表示され、実行中のジョブはキャンセルできます。完了したジョブは7日間一覧に残ります。

ダッシュボードを開ける人なら誰でもこのタブを開けますが、表示されるのは、その人が権限を持つ機能のジョブだけです。数字の意味については [バックグラウンドジョブ](/ja/community/levels#background-jobs) を参照してください。

## Audit Log（監査ログ）

<DashboardLink to="settings/audit">**Audit Log**</DashboardLink> タブには、Heimdallのダッシュボードで行われた操作が記録されます。どのスタッフが設定を変更したか、カテゴリを作成または削除したか、権限を変更したか、などです。これはDiscordのサーバーの監査ログとは別のものです。

各項目には次の内容が表示されます。

| 項目 | 説明 |
| --- | --- |
| **Timestamp**（日時） | 操作が行われた日時 |
| **User**（ユーザー） | 操作を行ったダッシュボードのユーザー |
| **Action**（操作） | 変更された内容（例：「Permission override updated」「Category deleted」） |
| **Details**（詳細） | 変更内容の概要。該当する場合は変更前と変更後の値を含みます |

監査ログは読み取り専用で、消去することはできません。項目は直近90日間保持されます。

## 必要な権限

| 操作 | 権限キー |
| --- | --- |
| 全般設定の閲覧と変更 | `dashboard.manage_settings` |
| ロールとユーザーの権限の閲覧と変更 | `dashboard.manage_permissions` |
| ファイルストレージの設定の管理 | `file-storage.manage_config` |
| 監査ログの閲覧 | `dashboard.manage_permissions` |
